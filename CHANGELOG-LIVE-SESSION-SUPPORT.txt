HASDEO BANK update - live refresh and session restore

1. Support form submissions are saved in the PostgreSQL support_tickets table and shown in Owner Panel > Support requests.
2. If Gmail SMTP is configured in Render (MAIL_USERNAME and MAIL_APP_PASSWORD), support submissions also trigger an email to ADMIN_ALERT_EMAIL. If SMTP is not configured, the ticket remains saved in the database and is still visible in the Owner Panel.
3. Added GET /api/session so the browser can restore the current admin/customer dashboard after a page reload while the server session cookie remains valid.
4. Dashboard account details and transactions now refresh automatically every 4 seconds, so a recipient sees a completed demo transfer without manually refreshing.
5. Explicit Sign out still invalidates the session. Session expiration, inactive customer status, or browser cookie removal can still require signing in again.
6. Added Spring Session JDBC so authenticated sessions are stored in PostgreSQL rather than only in application memory. This helps preserve valid sessions across application restarts and deployments. The existing 30-minute inactivity timeout remains.

Validation: app.js passed `node --check`. Maven build could not be run in this packaging environment because Maven is not installed. Run `mvn clean package` in Windows PowerShell before deployment. On first startup, Spring Session initializes its PostgreSQL session tables using the configured datasource.
